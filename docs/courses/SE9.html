About this course

This elective uses competitive-programming frameworks, contest-style tasks, and interview-style problems as applied laboratories for advanced algorithmic problem solving. Students learn to recognize problem structure, choose the appropriate algorithmic technique, prove correctness, analyze complexity, and implement robust solutions under realistic time and memory constraints.

The work combines formal algorithmic reasoning with extensive live demonstrations and in-class problem solving. Students study dynamic programming, graph algorithms, greedy methods, divide and conquer, advanced data structures, string algorithms, search, optimization, and reductions. Each topic is taught through construct-matched problems in which the algorithmic idea, the complexity bound, and the implementation are developed together. Algorithmic screening remains a central pathway into software-engineering roles, and the course uses that practical motivation to build the deeper academic competence a third-year elective demands: abstraction, recurrence design, invariants, exchange arguments, graph modelling, state-space search, and disciplined complexity analysis.

Course format. Thirteen weeks, four contact hours each: a two-hour lecture (technique, mathematical structure, proof method, complexity model, and common failure modes) and a two-hour practice session run as an active problem-solving lab. In practice, the instructor demonstrates solution discovery, students solve related tasks in pairs or small teams, and the class compares approaches against a shared analysis checklist. The weeks form five parts: Modelling, Complexity, and Search; Dynamic Programming and Optimization; Greedy, Divide and Conquer, and Data Structures; Graphs and Strings; and Integration, Interviews, and the Final Competition.
What you will build

Build a personal technique portfolio of solved problems: for each, a precise computational model, a chosen algorithm with a correctness argument, a complexity analysis, an implementation that survives edge cases and strict runtime limits, and a clear interview-style explanation. The term culminates in a timed internal programming contest with a written post-contest editorial and reflection.

Expected outcomes

  • Translate informal problem statements into precise computational models.
  • Select algorithmic techniques based on constraints, structure, and the target complexity.
  • Design dynamic programs using states, transitions, base cases, and reconstruction.
  • Apply graph algorithms to shortest paths, connectivity, ordering, matching-style modelling, and flows.
  • Use advanced data structures to reduce asymptotic cost in online and range-query problems.
  • Prove greedy algorithms with exchange arguments, cut properties, and matroid-style intuition.
  • Analyze time and memory complexity, including amortized and pseudo-polynomial bounds.
  • Implement solutions that handle edge cases, large inputs, and strict runtime limits.
  • Explain algorithmic choices clearly in a technical-interview setting.
  • Read contest and editorial solutions critically and map them to underlying CS principles.

Theoretical foundations

The concepts and results this course rests on.

  • Correctness: loop invariants, induction, exchange arguments, optimal substructure, and graph cut properties
  • Complexity: worst-case and amortized analysis, recurrence solving and the Master theorem, and pseudo-polynomial and bit-complexity bounds
  • Modelling: state-space construction, graph representation, constraint exploitation, and reductions between problem forms
  • Dynamic-programming theory: optimal substructure, overlapping subproblems, and disciplined state and transition design
  • Greedy theory: the greedy-choice property, exchange arguments, cut properties, and matroid intuition
  • Graph theory: shortest paths, spanning trees, connectivity and components, and flows and cuts
  • Optimization: binary search on the answer, monotone feasibility predicates, dominance pruning, and DP optimization patterns
  • Hardness awareness: NP-completeness, reductions, and approximation and heuristic intuition for intractable problems

Prerequisites

This is a Year-3 elective. It assumes the mandatory CS core and, in particular, fluent programming and completed algorithmic foundations. The first week includes a diagnostic problem set so students can identify review needs early. It additionally requires the specific prior background listed below.

Course-specific prerequisites:

  • Data structures: arrays, lists, stacks, queues, trees, hash tables, heaps, balanced trees, and union-find
  • Design and analysis of algorithms: sorting, searching, recursion, graph traversal, shortest paths, asymptotic notation, and correctness proofs
  • Graph theory foundations
  • Programming fluency in C++, Java, C#, or Python, with standard-library containers, debugging, and test-case construction

Greedy Algorithms and Exchange Arguments
LectureGreedy choice, exchange proofs, cut properties, interval scheduling, Huffman-style merging, and counterexample search; when a locally best step can be proven never to hurt a global optimum.
PracticeBuild proof sketches and test greedy hypotheses against adversarial cases: Jump Game, Non-overlapping Intervals, Task Scheduler, and Minimum Arrows.

Divide and Conquer, Binary Search on the Answer, and Recurrences
LectureRecurrence analysis, monotone feasibility predicates, parametric search, mergesort-style counting, and selection; when the solution space is ordered or recursive splitting exposes useful counts.
PracticeSolve inversion counting, closest-pair variants, and feasibility-search tasks: Koko Eating Bananas, Search in Rotated Sorted Array, Count of Smaller Numbers After Self, and Median of Two Sorted Arrays.

Advanced Data Structures for Problem Solving
LectureUnion-find, Fenwick trees, segment trees, sparse tables, monotonic stacks, monotonic queues, and heaps; turning repeated updates, range queries, and dynamic components into efficient operations.
PracticeTransform O(n²) scans into O(n log n) or O(n) data-structure solutions: Range Sum Query Mutable, Sliding Window Maximum, Daily Temperatures, and Accounts Merge.
DeliverableData-structure comparison table for three range-query tasks.
WatchEN: Fenwick Trees · HE: Union-Find

Wk 8
Graph Modelling and Traversal Patterns
LectureBFS, DFS, topological sorting, connected components, bipartite tests, shortest unweighted paths, and implicit and grid graphs; modelling non-graph statements as graphs.
PracticeCompare adjacency representations and model reachability, dependency, and state-transition problems: Course Schedule, Rotting Oranges, Pacific Atlantic Water Flow, and Word Ladder.
DeliverableOne implicit-graph problem and one dependency-order problem.
WatchEN: Depth-First Search · HE: Algorithms playlist
Wk 9
Shortest Paths, Spanning Trees, SCCs, and Flow Ideas
LectureDijkstra, Bellman-Ford, Floyd-Warshall, minimum spanning trees, bridges, strongly connected components, and residual-network intuition for maximum flow.
PracticeChoose the correct graph algorithm from weights, constraints, and required output: Network Delay Time, Cheapest Flights Within K Stops, Critical Connections, and Min Cost to Connect All Points.
DeliverableGraph-algorithm selection memo for a mixed problem set.
WatchEN: Dijkstra (MIT 6.006) · HE: Bellman-Ford and APSP
Wk 10
String Algorithms and Hashing
LecturePrefix functions, KMP, rolling hash, tries, suffix-array intuition, sliding-window counts, and collision risk; connections to string DP.
PracticeSolve pattern matching, dictionary, palindrome, and repeated-substring problems: Implement Trie, Find All Anagrams, Repeated DNA Sequences, and Longest Duplicate Substring.
DeliverableOne exact matcher and one hash-based solution with a collision discussion.
WatchEN: KMP and String Search · HE: Strings, tries, and suffixes

Wk 11

LectureNP-completeness awareness, reductions, approximation intuition, heuristics, dominance pruning, and state compression; recognizing when exact polynomial solutions are unlikely.
PracticeClassify tasks as polynomial, pseudo-polynomial, exponential with pruning, or likely intractable: Partition to K Equal Sum Subsets, Sudoku Solver, Shortest Path Visiting All Nodes, and Word Ladder II.

AI tools in this course.

AI assistants may support review and explanation: exploring an unfamiliar technique, generating alternative solutions to compare, or checking a complexity claim. Two conditions keep the learning genuine. First, every submitted solution must include the student's own reasoning, tests, and complexity analysis, and the student must be able to explain and defend it. Second, the graded core of the course is exactly what an assistant cannot do for a student under contest and interview conditions: modelling a problem from scratch, deriving and proving the algorithmic step, and communicating a solution aloud while it is questioned. Assistants are treated as a study aid, not a substitute for the reasoning the assessment measures.

Technique portfolio and final contest

This course has no running team project. Its major assignment is a personal technique portfolio built across the term and a final internal programming contest. The portfolio is a curated set of solved problems, each documented with a computational model, state or graph design, a correctness argument, complexity analysis, tests, and an interview-style explanation. Grading weights the parts an AI assistant cannot do for the student: modelling from scratch, proving the algorithmic step, and defending the solution under questioning.

Requirements

  • Solve real problems end to end: model, algorithm, proof sketch, complexity analysis, implementation, and tests, not disconnected code snippets.
  • Cover the breadth of the course: at minimum dynamic programming, graphs, greedy, divide and conquer, advanced data structures, and strings.
  • Show technique transfer: for each problem, state the invariant, justify the data structure, and connect the implementation to the complexity claim.
  • Handle edge cases, large inputs, and strict runtime limits, with reproducible local tests.
  • Compete in the final internal contest and submit a post-contest editorial and an individual reflection on strategy and technique selection.

Assessment & grading

Grading combines practical problem-solving performance with explicit academic evidence: solutions, proofs, complexity analyses, and reflections that show technique transfer. There is no written final exam.
