About this course

This elective takes students beyond isolated programming exercises into the engineering discipline of building enterprise-grade backend systems with C# and modern .NET. The work is domain modelling, use-case design, quality attributes, API contracts, persistence boundaries, integration patterns, security architecture, and architecture documentation, all in service of one goal: building systems whose design can be explained, reviewed, extended, and defended.

No prior .NET experience is assumed. The course builds the .NET foundations early, then uses one running project to introduce architecture styles, architectural decision making, enterprise design patterns, robust API design, security, enterprise integration, and AI-API integration through explicit application boundaries. Enterprise software is not about making endpoints respond; it is about aligning business use cases, domain rules, persistence, external integrations, quality attributes, security constraints, and team-readable code.

Course format. Thirteen weeks, four contact hours each: a two-hour lecture (concepts, architecture, and design reasoning) and a two-hour practice session at the keyboard. The course is project-based; teams carry one running enterprise application end to end and present it three times, in weeks 5, 8, and 13. The weeks form six parts: .NET Foundations, API Contracts and Persistence, Enterprise Architecture and Design Tradeoffs, Domain Logic and Security Architecture, Integration and AI-Enabled Systems, and the Final Architectural Defence.
What you will build

Build one enterprise backend application end to end: an ASP.NET Core Web API over a domain model persisted with Entity Framework Core, structured with Clean Architecture, applying GoF and enterprise design patterns, secured with authentication, authorization, and audit trails, integrated with Azure services and an AI API behind a governed application boundary, documented with UML and C4 diagrams and ADRs, and defended in a final architecture review.

Expected outcomes

  • Develop enterprise applications using C#, modern .NET, and ASP.NET Core.
  • Design RESTful APIs with explicit DTOs, validation, versioning, and error handling.
  • Use Entity Framework Core for persistence, migrations, relationships, and database access.
  • Structure applications with layered architecture, Clean Architecture, and modular design.
  • Apply GoF and enterprise design patterns where they clarify boundaries and reduce coupling.
  • Evaluate architecture using quality attributes, scenarios, ADRs, and explicit tradeoffs.
  • Design security architecture with authentication, authorization, validation, auditability, and error contracts.
  • Use contract thinking and architecture checks to protect business logic, API behaviour, and dependency rules.
  • Use .NET platform capabilities such as reflection, serialization, HttpClientFactory, hosted services, caching, resilience, async concurrency, and background work.
  • Integrate AI APIs and .NET AI libraries behind replaceable, governable application boundaries.
  • Document architecture decisions with UML, C4 diagrams, ADRs, pattern explanations, and tradeoffs.
  • Defend a complete enterprise application from use case to implementation detail.

Theoretical foundations

The concepts and results this course rests on.

  • Quality attributes (modifiability, scalability, reliability, security, observability, deployability, cost) as architecture drivers, not afterthoughts
  • Coupling and cohesion: afferent and efferent dependencies, instability, abstraction, and dependency inversion
  • Modelling languages: UML use-case, class, and sequence diagrams and C4 as compact ways to reason about structure and collaboration
  • Contracts and invariants: API contracts, domain invariants, preconditions, postconditions, and consistency boundaries
  • Pattern theory: GoF categories, intent, forces, and consequences, and reusable design knowledge versus unnecessary ceremony
  • Distributed-system principles: latency, partial failure, idempotency, retries, timeouts, and eventual consistency
  • Concurrency theory: threads, tasks, synchronization, cancellation, and why non-blocking code is not automatically parallel code
  • Security theory: threat modelling, least privilege, trust boundaries, claims, policies, auditability, and data exposure
  • AI-system theory: non-determinism, context construction, evaluation sets, model risk, tool-use boundaries, and human accountability

Prerequisites

This is a Year-3 elective. It assumes the mandatory CS core: data structures and algorithms, operating systems, databases, and software engineering, together with the core mathematics. It additionally requires the specific prior background listed below; no prior .NET experience is assumed.

Course-specific prerequisites:

  • Programming and basic object-oriented design
  • Databases: relational tables, keys, joins, transactions, and basic SQL
  • Basic web development: HTTP, REST, and JSON
  • Git and a basic DevOps workflow

AI tools in this course.

Using an AI assistant is encouraged; it reflects how modern software engineering is increasingly done. Two conditions keep the learning genuine: students keep full ownership of, and responsibility for, everything they submit, and must be able to explain and defend any part of it. Every weekly increment follows a three-part model. Part A, build: use an assistant to explore framework APIs, generate examples, compare designs, or find refactoring options. Part B, run and inspect: run the code, read it, check edge cases, remove secrets from prompts, and confirm the generated code matches the architecture. Part C, review and defend: explain the design and its tradeoffs, where it would fail, and why each pattern or boundary belongs in the system. Because the course grades exactly what an assistant cannot do for a student, defending architecture under questioning, every generated artifact is reviewed before it ships.

Student project

Teams of three or four carry a single enterprise application across the semester, integrating most of the covered material into one coherent system: a business domain, use cases, a REST API, a persistent data model, a layered or Clean Architecture structure, enterprise design patterns, security, validation, integration boundaries, documentation, and an optional AI-backed use case. Grading weights the parts an AI assistant cannot do for the student: reasoning about architecture, measuring tradeoffs, and defending design decisions. Each presentation is twelve to fifteen minutes plus questions, with a short written report and a tagged release of the repository.

Requirements

  • Build a coherent enterprise system, not a set of disconnected exercises, and demonstrate architectural maturity rather than endpoint count.
  • Choose one of the course domains or propose another of comparable scope for approval.
  • Show real depth: a real domain, use-case coverage, and engineering tradeoffs that are measured and documented rather than assumed.
  • Carry one running project from proposal to a deployed, defensible result across the whole term.
  • Work in a team of three or four and defend the design at each of the three presentations (weeks 5, 8, and 13).

Assessment & grading

Grading is project-based, with no written exam. Teams of three or four present one running enterprise application three times, with weight on architecture, reasoning, maintainability, use-case coverage, integration design, and the ability to defend design decisions.

Tools & platforms

  • Azure Service Bus & Functions: messaging and event-driven integration
  • Application Insights: telemetry, tracing, and diagnostics

  • OpenAI .NET SDK: call AI APIs behind a governed application boundary
