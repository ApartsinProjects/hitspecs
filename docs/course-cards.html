Course Card: Cloud Computing & Cloud-Native Platforms SE1 Intelligent Software Systems

Target Job Role & Responsibilities

Cloud & Platform Engineer

Designs and builds scalable cloud applications, choosing the right compute, storage, networking, and managed-service patterns for each workload and provisioning them as reproducible infrastructure. Owns the availability, latency, throughput, and cost trade-offs for production delivery.

Tools & Platforms to Master

  • Containers & orchestration: Docker, Kubernetes, Helm, Istio, kubectl
  • Infrastructure as code: Terraform
  • Serverless & managed AWS: Lambda, S3, RDS, DynamoDB, SQS, SNS, API Gateway, CloudFront
  • Data & cache: PostgreSQL, Redis
  • Observability: Prometheus, Grafana
  • Load testing: k6
  • Security: Trivy
  • Cloud platform: Amazon Web Services

Engineering & Science Concepts

  • Compute placement: VMs, containers, Kubernetes, serverless, managed platforms
  • Cloud storage semantics: object, block, file, relational, document, key-value, cache, queue, stream
  • CAP theorem and availability / consistency / partition-tolerance trade-offs
  • Replication, partitioning, indexing, caching, and eventual-consistency models
  • Stateless service design, idempotency, backpressure, retries, timeouts, circuit breakers
  • Declarative desired-state reconciliation control loops
  • Queueing theory and tail-latency analysis under load
  • Autoscaling control theory and capacity-versus-cost models
  • Supply-chain provenance and reproducible-build / deployment safety

Capstone Project

A non-trivial end-to-end scalable cloud application with:

  • An API service plus asynchronous background workers behind durable queues or events
  • Durable persistence (relational or NoSQL) plus object storage
  • Caching and CDN content delivery
  • Containerized and/or serverless deployment with a justified compute choice
  • Infrastructure provisioned declaratively via Terraform across dev and production-like environments
  • Load testing (k6) and SLO-tied dashboards and alerts (Prometheus, Grafana)
  • A defense with architecture diagrams, load-test evidence, failure-mode analysis, and a cost report

  • API testing: Postman/Newman, REST Assured, Schemathesis, Pact
  • AppSec: Semgrep, OWASP ZAP, Snyk, Trivy, OWASP Threat Dragon
  • Accessibility & performance: axe DevTools, k6
  • CI & observability: GitHub Actions, OpenTelemetry, Prometheus, Grafana

  • Saltzer and Schroeder protection principles and least privilege
  • STRIDE threat modeling over data-flow trust boundaries; OWASP Top 10
  • Black-box design: equivalence partitioning, boundary-value, decision tables, pairwise, state-transition
  • White-box and fault-based design: coverage criteria, mutation testing, risk-based testing
  • QA artifacts: test strategy, traceability matrix, defect lifecycle, release-readiness evidence
  • Software quality metrics: defect density, coverage, mutation score, complexity, SLO attainment
  • Static data-flow / taint analysis and soundness trade-offs

Capstone Project

A non-trivial end-to-end hardened, tested, and reliable web application with:

  • A threat model (OWASP Threat Dragon) and full OWASP Top 10 remediation
  • QA artifacts: test plan, risk and traceability matrices, defect register, quality dashboard, release report
  • Automated unit, integration, contract, E2E, cross-browser, accessibility, and mutation tests

  • Symmetric primitives: block ciphers, modes of operation, authenticated encryption
  • Public-key schemes: RSA, ElGamal, elliptic-curve cryptography
